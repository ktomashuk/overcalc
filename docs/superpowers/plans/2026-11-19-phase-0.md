# Phase 0 Implementation Plan — Tracer Bullet + Coding Agent

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A green, enforced quality gate (lint, types, architecture, tests, E2E in CI), the first harness pieces (guardrails, lint hook, `implementer` agent, PR template), and slice 0: `GET /health/ready` checks Postgres in docker compose.

**Architecture:** A uv workspace with one service, `services/calculation`. Phase 0 has no business module yet, so the four layers sit at service level (`overcalc_calculation.{domain,application,infrastructure,presentation}`), which matches the ARCHITECTURE.md §6 import-linter contract exactly. Readiness is a port (`ReadinessProbe`) with a SQLAlchemy adapter and a fake. Presentation is the composition root.

**Tech Stack:** Python 3.12, uv 0.13.9 workspace, FastAPI + uvicorn, SQLAlchemy 2 async + asyncpg, pydantic-settings, pytest + pytest-asyncio + httpx + testcontainers, ruff, mypy --strict, import-linter, pre-commit, Docker + compose, GitHub Actions, Claude Code project config (`.claude/`).

**Spec:** `docs/superpowers/specs/2026-11-19-overcalc-architecture-design.md` (§6.3 Phase 0, §7.2, §7.3, §10) and `ARCHITECTURE.md`.

## Global Constraints

- Python `>=3.12`; `.python-version` = `3.12`.
- Layer rules, per-layer libraries, naming and testing rules: ARCHITECTURE.md, verbatim. Pydantic/FastAPI/SQLAlchemy never in `domain/` or `application/`.
- `.importlinter` = ARCHITECTURE.md §6 contract set, verbatim.
- ruff `flake8-tidy-imports` bans relative imports beyond the same package (`ban-relative-imports = "parents"`).
- `mypy --strict`. No `# type: ignore` / `# noqa` without a reason comment and a PR callout.
- One ticket per PR, soft limit ~400 changed lines excluding `uv.lock`.
- Conventional commits; footer `Refs: OVC-<n>`. Branch names `OVC-<n>-short-slug`.
- Agents push from `ktomashuk-bot`; never merge, never force-push, never push to `main`.
- The bot token lives only in `.claude/settings.local.json` (gitignored). It never appears in a committed file.
- E2E = pytest + httpx against `docker compose`, also in CI.
- `docker compose up` = core only (Postgres + calculation). Profiles come later.
- Dependencies are added with `uv add` (latest compatible). `uv.lock` is committed; CI uses `uv sync --frozen`.

## Review Focus

1. **Postgres down or unreachable** → `/health/ready` answers **503** with `checks.db = "unavailable"` within ~probe timeout (2 s), not a 500 and not a hang. → Task 8 (contract tests incl. unroutable host).
2. **App boots before Postgres is up** (compose race, restarts) → the app starts anyway, reports 503 until the DB appears. No connect at import or startup. → Task 9 `test_app_starts_without_database`.
3. **Bot token leaks** via a careless `.gitignore` edit → a test fails if `.claude/settings.local.json` stops being ignored or `.claude/settings.json` becomes ignored. → Task 4.
4. **Lint hook gets weird input** (non-Python file, deleted file, malformed payload, unfixable error) → no-op with exit 0, except unfixable errors → exit 2 with ruff's message on stderr. → Task 5.
5. **A check that never fails is worthless** (misconfigured import-linter root, mypy not seeing tests) → each gate is seen failing once on a deliberate violation before it's trusted. → Task 2 verification steps.
